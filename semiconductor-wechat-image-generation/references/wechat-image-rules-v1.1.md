# 微信公众号技术文章配图生成规则 V1.1（完整执行版）

**确认日期：2026-10-29**

**适用范围：**半导体测试、功率器件、ATE、SiC/IGBT、Probe Card、可靠性测试、工程技术及 AI 技术类微信公众号文章。

**核心原则：**原文优先、封面独立生成、每章独立生成、视觉统一、技术准确、严格命名、逐张验收、完整交付。

---

## 一、最高优先级规则

### 1.1 一篇文章对应一套完整图片

标准结构：

- 封面：1 张。
- 正文：每个符合规则的大章节各 1 张。
- 总结：1 张。

每种图片只需要一张正式版本，不需要同一章节生成多个风格版本。

图片总数 = 1 张封面 + 正文大章节数量 + 1 张总结图。

### 1.2 每张图片必须独立生成

必须使用图像生成模型，逐张独立生成每张图片。

严格禁止：

- 先生成九宫格、总览图或多章节拼图，再裁切成单张。
- 将一张图片修改标题后冒充不同章节。
- 使用低分辨率拼图放大后交付。
- 将封面直接当作正文配图。
- 用 Python 绘图、PPT 模板或简单矢量卡片替代要求的原生图片生成。
- 将尚未生成的图片标记为已完成。

允许使用后期工具进行必要的尺寸调整、精确文字排版和文件整理，但不得以此替代逐张独立生成。

### 1.3 严格沿用已确认的历史风格

“按照历史规则生成”表示沿用已确认的蓝白高信息密度半导体工程信息图风格。

优先级：

1. 本次任务提供的明确版式参考图。
2. 同一篇文章已经确认的前序章节图片。
3. 已确认的历史公众号配图。
4. 本规则中的通用规范。

不得自行改成另一套模板，不得为了所谓视觉优化重新发明整套版式。

默认不使用 Adobe 重新设计配图；按照已确认的图片生成方式逐张生成。

## 二、生成前必须完整解析 Markdown

正式生成之前，必须完整读取文章 Markdown，建立图片任务清单。

任务清单至少包括：

- 文章正式标题。
- 全部大章节标题及原文顺序。
- 每章核心观点、关键公式、参数和工程结论。
- 需要表现的实物、流程、波形、结构图和对比图。
- 图片类型、文件名、目标尺寸。
- 生成状态、验收状态及返工记录。

### 2.1 章节识别规则

通常以 Markdown 的 `##` 作为大章节识别依据。

- `###` 及更低层级的小节整合到所属大章节图片中。
- 导语如果是独立的 `##` 章节，且没有明确排除，则单独生成一张。
- 总结单独生成一张。
- 参考资料通常不单独生成正文配图。
- 不得合并两个大章节，也不得因主题相似而减少图片数量。

如文章具有明确的特殊章节结构，以用户指定的实际结构为准。

### 2.2 内容来源

必须以正式 Markdown 为内容依据。

禁止：

- 擅自更改章节标题。
- 将其他章节内容混入当前图片。
- 遗漏关键工程逻辑。
- 编造实验数据、参数、标准或技术结论。
- 将推测内容表达成已验证事实。
- 为了画面美观改变公式、流程顺序或技术含义。

## 三、图片尺寸与比例（强制执行）

### 3.1 封面

- 目标尺寸：**2350 × 1000 px**。
- 目标宽高比：**2.35:1**。
- 格式：PNG。
- 用途：微信公众号消息列表横版封面。

封面必须独立生成，不得使用正文图代替。

标题与核心视觉主体必须位于安全区域，避免微信展示裁切。

不得直接拉伸图片改变比例。若生成工具无法直接输出目标尺寸，应通过保持比例的高质量缩放或画布处理达到目标尺寸，并检查最终文件。

### 3.2 正文配图

- 目标尺寸：**1573 × 1000 px**。
- 目标宽高比：约 **1.573:1**。
- 格式：PNG。
- 每个大章节独立一张。

每张图片必须完整表达对应章节的核心技术逻辑，不能套用封面比例。

### 3.3 总结图

- 目标尺寸：**1573 × 1000 px**。
- 目标宽高比：约 **1.573:1**。
- 格式：PNG。
- 独立生成。

总结图应体现全文的关键逻辑、工程结论和实践建议，不是简单重复章节标题。

### 3.4 尺寸优先级

1. 实际像素尺寸。
2. 正确宽高比。
3. 关键文字、图形和技术内容完整。
4. 清晰度与整体视觉质量。

不得仅凭提示词宣称尺寸合格，必须核验最终文件的实际尺寸。

## 四、统一视觉设计规范

### 4.1 整体风格

采用已经确认的：

**蓝白高信息密度工程技术信息图风格。**

视觉特点：

- 干净的白色或浅蓝背景。
- 深蓝标题和蓝色章节分区栏。
- 浅蓝色信息卡片。
- 细蓝色边框、清晰的流程箭头。
- 真实半导体设备、器件和测试场景。
- 工程流程、公式、波形、数据对比和 Wafer Map 相结合。
- 底部深蓝色 Takeaway 核心结论栏。

### 4.2 参考版式

以用户提供的章节参考图为视觉标准。

正文图优先采用以下组织方式：

1. 顶部：章节标题及必要的简短导语。
2. 主体：根据章节内容组织多个技术信息区域。
3. 中部或下部：展示关键流程、公式、数据、工程条件或风险。
4. 底部：深蓝色 Takeaway 栏。

各章节可以根据实际内容改变主体布局，但必须维持统一的标题、配色、分区风格、字体层级和专业程度。

**统一的是视觉规范，不是每张图片的具体内容和构图。**

### 4.3 色彩规范

- 主色：科技蓝、深蓝。
- 背景：白色、浅蓝、浅灰。
- 绿色：PASS、正常、正确状态。
- 红色：FAIL、风险、异常状态。
- 橙色：警告、边界状态或需要关注的条件。

避免无意义的霓虹色、过度渐变和装饰性光效。

### 4.4 实物场景

根据章节内容合理选择：

- ATE 自动测试设备。
- Probe Card、Probe Tip、Wafer、Pad/Bump。
- Socket、Contactor、Load Board、DIB。
- DUT、功率半导体芯片和功率模块。
- 示波器、测试波形和参数曲线。
- 可靠性设备、温度控制设备、测试治具。
- 真实的机械接触、电气路径和测试场景。

禁止为了丰富画面添加无关设备、虚构读数或明显不符合工程原理的结构。

---

## 五、封面设计规则

封面必须体现文章的核心主题。

要求：

1. 使用文章正式标题。
2. 突出文章最核心的技术对象或工程问题。
3. 采用真实设备、芯片、测试平台或有明确技术意义的视觉主体。
4. 可以加入少量核心信息卡、数据元素或工程线条。
5. 避免过多文字堆积。
6. 标题和主体必须处于安全区域。
7. 不得把封面制作成密集的正文信息图。
8. 不得擅自添加企业 Logo、宣传口号或未经确认的技术结论。
9. 不得使用正文图代替封面。
10. 最终核验尺寸为 2350 × 1000 px，比例为 2.35:1。

---

## 六、正文配图规则

### 6.1 每张图片必须具备的内容

每张正文图应包含：

1. **原始章节标题：**直接使用 Markdown 对应的大章节标题。
2. **核心观点：**准确提炼本章最重要的工程结论。
3. **主体视觉：**真实设备、结构示意、测试流程、波形、数据图或技术架构。
4. **逻辑关系：**通过箭头、分区、对比或因果链表达。
5. **关键参数：**保留本章不可缺少的电压、电流、温度、时间、型号、单位及测试条件。
6. **辅助说明：**使用必要的短句、图例和注释解释技术含义。
7. **核心结论：**底部深蓝色 Takeaway，概括本章结论。

### 6.2 内容与章节严格对应

一张正文图只能对应一个大章节。

生成前必须确认：

- 章节标题与 Markdown 完全一致。
- 图片的主要内容来自当前章节。
- 章节中的关键公式、流程、参数及工程结论没有遗漏。
- 不把其他章节的核心内容移入本章。
- 不使用文章总标题代替章节标题。

**不能只因为图片看起来专业，就判定它符合要求。内容匹配优先于视觉效果。**

### 6.3 不同章节采用不同的信息组织方式

根据内容选择最合适的工程表达：

- 流程类：步骤卡片和方向明确的箭头。
- 原理类：结构图、公式、因果关系。
- 对比类：左右对照、Before/After。
- 参数类：曲线、坐标轴、单位和测试条件。
- 失效分析类：Failure Path、排查流程、证据链。
- 误区类：错误认知与正确理解对照。
- 管理类：指标体系、趋势关系、管理流程。
- 检查清单类：编号卡片和勾选项。
- 总结类：关键结论与完整逻辑链。

不允许为了套用固定模板而改变章节原本的技术逻辑。

## 七、标题规范（今日新增，强制执行）

### 7.1 正文标题统一

除封面外，所有正文和总结图片必须采用统一的标题系统：

- 标题字体统一。
- 标题字号统一。
- 字重统一。
- 标题栏高度和位置统一。
- 一律左对齐。
- 标题颜色统一使用深蓝色或历史参考图中的深蓝色。
- 标题与主体内容之间保留一致的视觉间距。

建议统一采用顶部深蓝标题栏，标题左对齐；若同一篇文章已确认其他标题栏样式，则直接继承该样式。

### 7.2 标题必须来自 Markdown 原文

必须原样保留章节标题，包括：

- 中文章节序号。
- 英文专业术语。
- 标点符号。
- 括号和必要的限定词。

不得为了适应画面而随意改写、缩短、重新概括或更换标题。

如原文标题过长，应优先优化排版、字号适配和留白，不得擅自改标题。

### 7.3 正文图与封面区分

封面显示文章正式标题。

正文显示对应大章节的原始标题。

总结显示原文总结标题，或按照正式规则使用“总结”作为标题。

**正文图禁止反复出现文章总标题作为主标题。**

## 八、内容密度与可读性

### 8.1 信息密度

采用历史确认的高信息密度工程图风格，但不能把整篇 Markdown 原文塞入图片。

优先展示：

- 关键原理。
- 工程流程。
- 关键参数。
- 物理关系。
- 重要对比。
- 数据变化。
- 风险点。
- 工程结论。

### 8.2 字体与可读性

- 中文必须清晰、准确。
- 英文专业术语保持规范。
- 不得让卡片文字过小。
- 不得出现大量乱码或错别字。
- 不得让文字被设备、图片或边框遮挡。
- 不得因信息过多导致主体内容无法阅读。

如果内容无法在一张图中清晰呈现，应优先保留本章最重要的逻辑，适当压缩次要说明；不能通过无限缩小字体解决。

### 8.3 专业术语

根据上下文保留常见专业术语，例如：

ATE、DUT、Wafer Sort、Probe Card、Probe Tip、Contact Resistance、Overdrive、Planarity、Cres、First Pass Yield、Retest Recovery、Site-to-Site、Guardband、Correlation、Signal Integrity、Runtime、Configuration Snapshot。

不强行把所有英文术语翻译成中文。

## 九、公式、数据和工程准确性

### 9.1 公式

必须逐项核对原文公式。

例如：

`Vmeas = VDUT + I × Rcontact + I × Rpath + Measurement Error`

不得随意更改变量定义、正负号、单位或计算关系。

### 9.2 数据

原文没有提供具体数值时，不得把模型生成的数字包装成真实实验结果。

如确实需要使用示意数据，必须明确标注“示例”“示意”或“Example”。

### 9.3 图表

图表必须具有明确含义：

- 坐标轴和单位正确。
- 图例含义清楚。
- 数据变化方向符合原文。
- 对比条件一致。
- 不把示意曲线伪装成实测数据。

### 9.4 工程逻辑

所有流程、因果链和测试关系必须与原文一致。

不确定的技术信息不得凭空补齐；应省略不确定细节或在生成前提出确认。

## 十、流程箭头与辅助图规则

当原文包含重要箭头链，例如：

`A → B → C`

或：

`A ↓ B ↓ C`

必须逐项核对原文后再生成。

要求：

1. 步骤顺序正确。
2. 节点名称正确。
3. 不增加原文不存在的步骤。
4. 不删除原文已有的步骤。
5. 不改变概念关系。
6. 箭头方向清晰。
7. 多条并行链路不得混淆。
8. 重要条件、分支和回退关系不得遗漏。

### 10.1 独立辅助图

如果用户明确要求额外生成箭头流程辅助图：

- 每条指定流程独立生成。
- 不强制添加章节序号。
- 流程主体占据主要画面。
- 减少与流程无关的说明。
- 不使用正文主图的密集 Takeaway 模板替代流程图需求。

辅助图属于额外图片，不得替代章节主图。

---

## 十一、同一文章的视觉继承规则

如果同一篇文章前面的章节已经通过验收，后续章节必须直接沿用前序图片的视觉体系。

必须保持一致的项目：

- 标题字体和字号。
- 标题左对齐方式。
- 标题栏高度和位置。
- 主色和辅助色。
- 卡片边框和圆角。
- 箭头风格。
- 字体层级。
- 图片与文字的比例。
- 主体信息密度。
- 底部 Takeaway 样式。
- 整体画面比例。

后续章节可以根据实际内容改变信息布局，但不能突然更换整套视觉风格。

**同篇文章已确认的前序图片，是后续图片最优先的视觉母版。**

## 十二、文件命名规则（强制执行）

每张图片的文件名必须使用对应的正式标题。

### 12.1 封面

固定命名：

`封面.png`

### 12.2 正文章节文件名

正文图片必须使用 Markdown 中对应大章节的原始标题作为文件名。

例如：

```text
一、第一性原理：Wafer Yield首先是一个“测量结果”.png
二、Probe Card到底在改变什么？先看最简单的一个公式.png
三、Contact Resistance为什么会直接制造“假坏Die”？.png
```

命名要求：

1. 章节标题必须与原文一致。
2. 不得自行缩写、改写或重新概括标题。
3. 不得用 `Chapter_01.png`、`Image_01.png` 等通用名称代替章节名称。
4. 不得给同一章节添加多个不同版本的正式文件。
5. 不得因为分批生成而改变命名规则。

### 12.3 封面和总结文件名

封面采用文章正式标题命名，例如：

```text
封面_Probe Card为什么会影响晶圆良率？很多“坏Die”，可能只是没有被正确测到.png
```

总结图采用原文总结标题命名。如果原文只有 `## 总结`，则使用：

```text
总结.png
```

文件名必须与图片实际内容对应。

### 12.4 文件名特殊字符处理

如果操作系统不允许使用某些字符，可以只替换文件系统不支持的字符，不得改写标题的实际文字含义。

文件名修改后，必须在最终交付清单中保留对应的原始章节标题，确保可追溯。

## 十三、输出目录与文件组织规则（强制执行）

建议统一使用以下目录结构：

```text
公众号配图交付包_文章名称/
│
├── 01_封面/
│   └── 封面_文章标题.png
│
├── 02_正文配图/
│   ├── 导语.png
│   ├── 第一大章节原始标题.png
│   ├── 第二大章节原始标题.png
│   └── ...
│
├── 03_总结/
│   └── 总结.png
│
├── 04_验收清单/
│   └── 图片交付验收清单.md
│
└── 05_最终压缩包/
    └── 公众号配图交付包_文章名称.zip
```

### 13.1 目录规则

- 封面、正文、总结分开存放。
- 图片文件名直接对应文章内容。
- 不将临时草图、失败图片和正式图片混在一起。
- 不将不同文章的图片混在同一交付目录。
- 不把多个章节拼成一张图片后放入正文目录。

### 13.2 正式图片与临时文件

临时草图、未通过验收的图片及返工版本必须单独管理。

正式交付目录只能包含最终验收通过的图片。

不得把文件名带有 `draft`、`test`、`failed` 或其他临时标识的文件当作正式版本。

## 十四、分批生成规则（强制执行）

如果一次无法生成全部图片，允许分批生成。

**分批只改变交付批次，不改变生成方法和视觉规范。**

### 14.1 分批原则

- 每张图片仍须独立生成。
- 不允许把多张图片拼在一起生成后再拆分。
- 不允许因为图片数量多而省略章节。
- 不允许为了减少生成次数而把多个章节合并。
- 不允许第二批重新设计版式。

例如，一篇文章需要18张图片，可以分成两批或多批完成。

### 14.2 分批任务记录

每一批必须记录：

- 本批计划生成的图片。
- 本批已经生成的图片。
- 本批验收通过的图片。
- 本批需要返工的图片。
- 尚未生成的图片。
- 下一批的起止章节。

### 14.3 批次之间的连续性

第二批必须沿用第一批已经验收的视觉规范，包括：

- 标题字号和左对齐方式。
- 主色及辅助色。
- 卡片布局风格。
- 信息密度。
- 实物图片表现方式。
- 流程箭头风格。
- 底部 Takeaway 栏。
- 图片比例及整体视觉层级。

**不能因为更换批次，就将后续图片重新设计成另一套风格。**

## 十五、正式生成流程（强制执行）

所有公众号配图必须遵循以下流程。

### 第一步：读取正式 Markdown

完整读取正文，识别文章标题、导语、大章节、小章节、总结和参考资料。

不得只根据文章标题或之前的对话印象直接开始生成。

### 第二步：建立完整图片任务清单

逐张登记：

- 图片序号。
- 图片类型。
- 原始章节标题。
- 对应的核心内容。
- 文件名。
- 目标尺寸。
- 生成状态。
- 验收状态。

先确定总数，再开始生成。

### 第三步：确认视觉母版

优先使用本次提供的参考图和同篇文章已经验收通过的前序图片。

如果用户指定某张图片作为直接参考，必须以该图为准，不得擅自换用其他历史模板。

### 第四步：先生成封面

封面单独生成，尺寸为2350 × 1000 px。

封面通过尺寸、标题、构图和清晰度检查后，再进入正文生成。

### 第五步：逐章独立生成

严格按照 Markdown 的原始顺序，一章一张。

每张图生成前，必须明确本章标题、核心内容、必要公式和技术逻辑。

生成后检查本章内容是否正确，再开始下一张。

### 第六步：生成总结图

独立生成总结图，尺寸为1573 × 1000 px。

总结必须来自正式文章，不得自行增加未经原文支持的结论。

### 第七步：逐张验收

所有图片完成后，统一检查内容、标题、文件名、尺寸、清晰度和视觉一致性。

### 第八步：打包交付

只有通过验收的图片才可以进入正式交付目录和 ZIP 压缩包。

## 十六、图片质量验收规则（强制执行）

每张图片必须进行以下检查。

### 16.1 标题检查

- 图片标题与 Markdown 原始标题一致。
- 正文标题一律左对齐。
- 正文标题字体和字号统一。
- 标题没有被裁切。
- 没有将文章总标题误用于正文图片。
- 没有错误的章节序号或标题。

### 16.2 内容检查

- 图片只对应一个大章节。
- 核心观点与原文一致。
- 关键技术内容没有遗漏。
- 不存在跨章节串内容。
- 流程顺序、箭头方向和因果关系正确。
- 公式、单位和变量定义正确。
- 没有虚构测试数据或标准。

### 16.3 视觉检查

- 蓝白配色符合历史规则。
- 标题栏、信息卡片和底部 Takeaway 风格统一。
- 图片主体和文字没有互相遮挡。
- 文字足够清晰。
- 实物图与本章主题相关。
- 不存在明显乱码、错字或错误标签。
- 没有不必要的留白或无意义装饰。

### 16.4 尺寸检查

封面：

- 2350 × 1000 px。
- 2.35:1。

正文和总结：

- 1573 × 1000 px。
- 约1.573:1。

尺寸调整不得导致图像变形、文字模糊或关键内容被裁切。

### 16.5 验收状态

每张图片只能标记为以下状态之一：

- `待生成`
- `生成中`
- `待验收`
- `验收通过`
- `待返工`

只有 `验收通过` 的图片才可以正式交付。

## 十七、返工与错误处理规则

如果发现图片错误，不得通过简单改名、重复使用旧图或把其他章节图片替代过来蒙混过关。

### 17.1 标题错误

标题错误时，必须重新生成或进行可靠的文字修正，并重新检查整张图片。

如果标题错误导致章节内容不匹配，应重新生成整张图。

### 17.2 内容错误

以下情况必须返工：

- 图片与章节主题不符。
- 内容来自其他章节。
- 缺少本章核心流程或关键结论。
- 公式、参数或单位错误。
- 箭头顺序错误。
- 关键工程逻辑被改变。
- 图片再次变成文章封面。

### 17.3 风格错误

如果后续图片与已确认的前序图片明显不一致，必须依据视觉母版返工。

不能用“新设计更美观”作为擅自换版式的理由。

### 17.4 数量错误

如果发现漏图，必须补齐缺失章节。

如果发现重复图，必须确认对应章节是否真正独立完成。

不能以图片总数正确代替章节覆盖完整性检查。

## 十八、禁止事项总表

以下行为一律禁止：

1. 将多章节总览图裁切成正式章节图。
2. 用一张图修改标题后冒充多个章节。
3. 把封面当作正文配图。
4. 将文章总标题反复用作正文标题。
5. 擅自更改 Markdown 标题。
6. 将多个大章节合并为一张图片。
7. 漏掉导语或总结等明确要求生成的图片。
8. 擅自改变章节顺序。
9. 生成没有原文依据的工程结论。
10. 虚构测试数据、波形、参数或实验结果。
11. 擅自更换已确认的历史视觉风格。
12. 使用低清拼图放大后作为正式图片。
13. 通过 Python 或 PPT 模板代替要求的原生独立图片生成。
14. 把未完成或未验收的图片标记为完成。
15. 将临时图和正式图混入同一交付目录。
16. 在图片中添加未经授权的企业信息、Logo 或宣传文字。
17. 为了美观而牺牲技术准确性。
18. 在没有实际文件的情况下声称已生成或已打包。

| 标题验收 | 通过或返工 |
| 清晰度验收 | 通过或返工 |

- 文件没有损坏。
- 不包含临时图或失败版本。
- 图片实际尺寸符合要求。

最终回复必须提供真实有效的压缩包下载链接，不能只报告已完成而不提供文件。
